# Agent Update: Dashboard Button + Upload UI + Bulk Update

## Current State
- `agent/src/main/updater.ts` has `checkForUpdates`, `downloadUpdate`, `applyUpdate` — but only reachable from Electron IPC, not Socket.IO
- `server/src/routes/agentUpdate.ts` has `update-check` and `download/:filename` — but `manifest.json` is a placeholder (`filename: ""`), no upload endpoint
- Protocol has `AgentEvent.UpdateResult` / `ServerEvent.UpdateAvailable` — dead code, unimplemented
- Dashboard has no update UI; `Device.agentVersion` goes stale after updates (not refreshed from status)

## Architecture

**Update flow**: Dashboard button → `dash:send-command` (`agent:update`) → Server relays → Agent runs `checkForUpdates` → `downloadUpdate` → `applyUpdate` → restarts. Progress via `AgentEvent.UpdateResult` + `CommandResult`.

---

## 1. Protocol changes (`shared/src/protocol.ts`)

- Add `'agent:update'` to `CommandType`
- Add `UpdateProgress` interface: `{ stage: 'checking'|'downloading'|'installing'|'done'|'error'; message: string; version?: string }`
- Wire `AgentEvent.UpdateResult` to carry `UpdateProgress` (already exists in enum)

## 2. Agent: handle remote update command (`agent/src/main/connection.ts`)

- Add `case 'agent:update'` in `handleCommand()`:
  - `checkForUpdates(serverUrl)` → emit `AgentEvent.UpdateResult` `{ stage: 'checking' }`
  - `downloadUpdate(serverUrl, manifest)` → emit `{ stage: 'downloading' }`
  - `applyUpdate(filepath)` → emit `{ stage: 'installing' }` then `{ stage: 'done' }`
  - On error → emit `{ stage: 'error', message }` + `CommandResult` with `success: false`
- Import from `updater.ts`
- Need `serverUrl` from `credentials.serverUrl` (already available)

## 3. Agent: refresh version on status (`server/src/socket/agentHandler.ts`)

- In `AgentEvent.Status` handler, add `agentVersion: payload.agentVersion` to the `Device.findByIdAndUpdate` call — fixes stale version after update

## 4. Server: upload endpoint (`server/src/routes/agentUpdate.ts`)

- `POST /api/agent/updates` (admin) — accepts multipart file upload (agent installer/appimage/dmg) + JSON body `{ version, platform, arch, notes }`
  - Saves file to `server/updates/`
  - Writes/updates `manifest.json` with `version`, `filename`, `downloadUrl: "/api/agent/download/<filename>"`, `platform`, `arch`, `notes`, `publishedAt`
- `DELETE /api/agent/updates/:filename` (admin) — removes an update file
- Use `multer` for file upload (add dependency) or raw `req` body parsing

## 5. Server: update command relay (no changes needed)

- `dash:send-command` already relays any `CommandType` to the agent — `agent:update` will flow through automatically
- Add `AgentEvent.UpdateResult` listener in `agentHandler.ts` → relay to dashboard as `dash:update-progress`

## 6. Dashboard: per-device "Update" button (`dashboard/src/pages/Devices.tsx`)

- **Table view** (line ~263): add "Update" button before Edit, `btn btn-secondary btn-sm`, disabled when `d.status !== 'online'`
- **Grid view** (line ~314): same button in `.device-card-actions`
- On click: `modal.confirm()` → send `agent:update` command via `dash:send-command` → listen for `dash:command-result` + `dash:update-progress` → show progress in a toast/banner
- Show agent version on device cards: `v{d.agentVersion}` (small text)

## 7. Dashboard: "Update All" button (`Devices.tsx`)

- Header button next to "Refresh": "Update All" (`btn btn-secondary btn-sm`)
- Confirm dialog → iterate all `status === 'online'` devices → send `agent:update` to each
- Show progress count ("Updating 3/5 devices...")

## 8. Dashboard: upload UI (new section in Settings or a modal)

- In `Settings.tsx` or a new "Agent Updates" section:
  - File upload input (accepts `.exe`, `.AppImage`, `.dmg`)
  - Version input (or auto-detect from filename)
  - Platform/arch selectors (or auto-detect)
  - Notes textarea
  - Upload button → `POST /api/agent/updates`
  - List current update files from `GET /api/agent/updates`
  - Delete button per file

## 9. Socket.IO event for progress

- `agentHandler.ts`: listen `AgentEvent.UpdateResult` → relay to `/dashboard` namespace as `dash:update-progress` with `{ deviceId, progress }`
- `Devices.tsx`: listen for `dash:update-progress` → update per-device update status
