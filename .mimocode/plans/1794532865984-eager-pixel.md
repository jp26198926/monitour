# Fix: Agent GUI shows "Connected" when server is down

## Root Cause

The GUI's "Connected" label is **fabricated**, not derived from the real socket state.

- `agent/src/main/electron.ts:217-224` — `startConnection()` starts a `statusTimer` that sends
  `agent-status` with a **hardcoded `connected: true`** every 10 s. It never consults the actual
  Socket.IO connection. So 10 s after launch, the GUI flips to "Connected" even if the server is
  unreachable (or was never running).
- `agent/src/main/connection.ts` tracks the socket (`socket.connected`, `connect`/`disconnect`
  events at lines 64–75) but exposes **no state getter and no callbacks**, so `electron.ts` has no
  way to know the real state.
- `agent/src/renderer/app.js:177-181` renders whatever `data.connected` says:
  `true → 'Connected'/online`, `false → 'Connecting…'/connecting`. The `offline` dot style
  (`index.html:166`) is defined but never used.

## Fix (3 files)

### 1. `agent/src/main/connection.ts` — expose real connection state

- Add to `AgentConnection`:
  - `public isConnected(): boolean { return this.socket?.connected ?? false; }`
  - `public onStatusChange?: (connected: boolean) => void;`
- Invoke `this.onStatusChange?.(true)` in the existing `socket.on('connect', …)` handler (line 64).
- Invoke `this.onStatusChange?.(false)` in the existing `socket.on('disconnect', …)` handler (line 72)
  and in `socket.on('connect_error', …)` (line 77) so the GUI updates promptly on failures too.

### 2. `agent/src/main/electron.ts` — report real state

In `startConnection()` (lines 193–225):
- Wire the callback right after creating the connection:
  `connection.onStatusChange = (connected) => { …send 'agent-status' with real `connected`… }`
  (guard `mainWindow && !mainWindow.isDestroyed()`, same as existing code).
- Change the `statusTimer` body to send `connected: connection.isConnected()` instead of `true`.
- Send `lastSeen: Date.now()` **only when actually connected** (omit otherwise) so the "Last seen"
  row doesn't tick while offline. The renderer already guards with `if (data.lastSeen)`.

### 3. `agent/src/renderer/app.js` — honest 3-state label (lines 177-181)

Track a module-level `wasConnected` flag and render:
- `data.connected` → dot `online`, label **"Connected"**
- `!connected && !wasConnected` → dot `connecting`, label **"Connecting…"** (initial state)
- `!connected && wasConnected` → dot `offline`, label **"Disconnected — reconnecting…"**

Uses the already-defined `.status-dot.offline` style (`index.html:166`). No HTML changes needed.

## Out of scope

- CLI entry `index.ts` (no GUI status display).
- Socket reconnection tuning (already `reconnection: true`, infinite attempts).
- `shared/protocol.ts` — the `agent-status` IPC payload is local to Electron IPC, not the
  server protocol, so no shared-type change required.

## Verification

1. `cd agent && npx tsc` — compile passes (also guard against the stale-`tsbuildinfo` issue from
   before: if output looks stale, remove `agent/tsconfig.tsbuildinfo` first).
2. **Server stopped**, run `cd agent && npm run dev`:
   - GUI shows "Connecting…" initially and stays "Connecting…" (or "Disconnected — reconnecting…"
     after a first connect) — **never "Connected"**.
3. Start the server (`cd server && npm run dev`):
   - Within a few seconds the GUI flips to **"Connected"** (green dot) via the `onStatusChange`
     callback — no 10 s wait.
4. Kill the server again:
   - GUI flips back to **"Disconnected — reconnecting…"** (grey `offline` dot) promptly.
5. "Last seen" time only advances while connected.
