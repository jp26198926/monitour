# Remote Cursor Overlay + Realtime Latency — Remote Desktop

## Goal

At `/devices/:id/desktop`, the operator must see the **remote client's real mouse cursor** — position *and* the actual icon (resize arrows, I-beam, hand) — with no perceptible delay. Today the OS cursor is invisible: both capture backends grab the framebuffer only, and the viewer shows a fake dot at the operator's own mouse.

**User-approved decisions:**
1. **Real cursor bitmaps** — agent streams actual cursor pixels (not a shape enum).
2. **Remote cursor only while controlling** — hide the browser crosshair (`cursor: none`); overlay renders at the **local** mouse position (instant, zero position lag) with the agent-supplied shape. View-only: overlay follows the agent-reported position/shape.
3. **30 FPS** stream (from 15) plus general latency fixes.

## Architecture

- Agent polls `GetCursorInfo` @30 Hz → emits position on change (`agent:cursor`) and pixel bitmap only when the cursor *shape* changes (`agent:cursor-shape`).
- Server relays both to dashboards (same broadcast pattern as `agent:frame` today) and caches the latest shape for late joiners.
- Dashboard draws the bitmap on a small overlay canvas positioned via the existing letterbox math. In control mode, position = local mouse (prediction); shape = last agent shape (~1 RTT delay on shape change only — inherent).
- Old agent / no cursor data → exactly today's behavior (crosshair + dot). Backward compatible.

## Step 2 — Agent

### 2a. NEW `agent/src/main/cursorCapture.ts`

Self-contained poller; bind user32/gdi32 via koffi (same pattern as `winInput.ts:124-129`, but its own `koffi.load` — don't couple to winInput internals).

FFI: `GetCursorInfo`, `GetIconInfo`, `DrawIconEx` (user32); `CreateCompatibleDC`, `CreateDIBSection`, `SelectObject`, `GetObjectW`, `BitBlt` (optional), `DeleteObject`, `DeleteDC` (gdi32). Constants: `CURSOR_SHOWING=1`, `DI_NORMAL=0x3`, `SM_CXSCREEN=0`, `SM_CYSCREEN=1`.

Struct layouts (x64): `CURSORINFO` = 24 bytes (DWORD cbSize, DWORD flags, HCURSOR hCursor, POINT ptScreenPos). `ICONINFO` = 32 bytes (BOOL fIcon, DWORD xHotspot, DWORD yHotspot, pad, HBITMAP hbmMask, HBITMAP hbmColor).

**API:**
```ts
export interface CursorSample { x: number; y: number; visible: boolean; shapeId: number; }
export function startCursorCapture(h: {
  onState: (s: CursorSample) => void;   // on change, ≤30 Hz
  onShape: (shape: CursorShape) => void; // once per shape change
}): () => void; // stop()
```

**Poll loop** (`setInterval` 33 ms):
1. `GetCursorInfo` → `visible = (flags & CURSOR_SHOWING) && pt in [0,SM_CXSCREEN)×[0,SM_CYSCREEN)` (primary-only, consistent with frame capture; pt can be negative on other monitors). Percent x/y via `GetSystemMetrics(SM_CXSCREEN/SM_CYSCREEN)` — the *same* source `winInput.toAbsoluteCoords` inverts, so injected-input % and reported-cursor % round-trip exactly under DPI virtualization.
2. Emit `onState` only when position (rounded to 0.01) or `visible` changed.
3. Shape: if `hCursor` handle changed → capture + emit. Also every 500 ms re-capture and FNV-1a/CRC32-hash the pixels to catch animated cursors that reuse the handle; hash change → new `shapeId`, emit.

**Bitmap capture** (`captureShape(hCursor)`):
1. `GetIconInfo` → hotspot; dims via `GetObjectW` on `hbmColor ?? hbmMask`. Height = `hbmColor ? bmHeight : bmHeight/2` (monochrome = AND+XOR stacked).
2. Top-down 32bpp DIB (`CreateDIBSection`, `biHeight = -h`) in a mem DC; `DrawIconEx(dc, 0, 0, hCursor, w, h, 0, NULL, DI_NORMAL)` — pass the HCURSOR directly (no CopyIcon/DestroyIcon needed).
3. Read DIB bits → BGRA. Alpha fix: if no pixel has `0<a<255`, set `a=255` where RGB≠0 (legacy icons blend onto black).
4. `DeleteObject` on `hbmMask`/`hbmColor`/DIB and `DeleteDC` — **leak discipline matters; this loops for hours**.

**Errors/locked sessions:** any FFI failure → log once, emit `visible: false`, keep polling (self-healing). Before sampling, if `getSessionState().locked` (from `lockState.ts:107`), call `attachToInputDesktop()` (already exported, `winInput.ts:138`) so we read the Winlogon desktop's cursor; if attach fails → `visible: false`. The lock-screen helper *frame* path (`connection.ts:243-285`, %TEMP% file poll) is out of scope for cursor — dashboard falls back (one-line comment there).

## Step 3 — Server (`server/src/socket/agentHandler.ts`)

Thin relays next to `agent:frame` (~line 124), same namespace-broadcast pattern as frames (no room-routing refactor — it doesn't affect single-viewer latency):

```ts
socket.on('agent:cursor', (payload) => {
  ns.server.of('/dashboard').emit('device:cursor-update', { ...payload, deviceId });
});
socket.on('agent:cursor-shape', (payload) => {
  cursorShapeStore.set(deviceId, { shape: payload.shape, ts: payload.ts }); // Map like thumbnailStore (~line 20)
  ns.server.of('/dashboard').emit('device:cursor-shape', { deviceId, shape: payload.shape, ts: payload.ts });
});
```

Shape cache replay: handle `dash:request-cursor-shape` (deviceId) on the dashboard connection block (~line 169, next to `dash:request-thumbnails`) → re-emit cached `device:cursor-shape`. Delete from `cursorShapeStore` in the agent `disconnect` handler (~154).

No other server changes. Do **not** enable `perMessageDeflate` (off by default; JPEGs/bitmaps are incompressible and compression adds latency). Keep mousemove relay unthrottled.

### 4c. Remote cursor overlay

**Refs (not React state — updates at 30-60 Hz without re-render):** `remoteCursorRef` (overlay `<canvas>`), `shapeRef` (last `CursorShape` + its decoded `ImageData`), `remotePosRef` (`{x, y, visible}`), `hasCursorDataRef` + a tiny `useState<boolean>` mirror for the CSS class.

**Ingest `device:cursor-shape`** (filter by deviceId): ignore if `shapeId <=` current; BGRA→RGBA byte-swap into `ImageData`; `putImageData` into the overlay canvas (canvas sized to `w×h`); `hasCursorData = true`.

**Ingest `device:cursor-update`**: store `remotePosRef`; reposition immediately only when **not** controlling.

**`placeRemoteCursor(pctX, pctY)`** — inverse of `updateCursor` (218-224), using `getLetterbox` on a container ref:
```
scale = displayW / canvas.width          // screen-px → display-px
el.style.width/height = shape.w/h * scale
el.style.left = offsetX + (x/100)*displayW - hotspotX*scale
el.style.top  = offsetY + (y/100)*displayH - hotspotY*scale
el.style.display = visible ? 'block' : 'none'
```
Hotspot lands exactly on the point (critical for resize-arrow accuracy).

**Control mode:** on `handleMouseMove`/`handleMouseDown` call `placeRemoteCursor(pos.x, pos.y)` — position is local and instant. Remote `cursor-update` events do **not** move the overlay while controlling (avoids fighting the prediction); only `visible` is taken from them. Add class `remote-cursor-active` to the container when `hasCursorData` → CSS `cursor: none`. Until first shape arrives: keep today's crosshair + `.desktop-cursor` dot fallback (keep the dot element; hide it whenever the overlay is active). `handleMouseLeave`: hide both.

**View-only:** overlay driven purely by `device:cursor-update`/`device:cursor-shape`. Optional light smoothing via one rAF lerp (`cur += (target-cur)*0.35`); if it feels mushy, direct-set instead. No full interpolation clock.

**Visibility:** hide on `visible:false`, mouseLeave, disconnect/`status!=='connected'`, and when a fresh agent reconnects (reset `hasCursorDataRef`/`shapeRef` on `device:status-update` offline so a stale `shapeId` can't mask a new agent's shape).

## Edge cases

| Case | Behavior |
|---|---|
| Remote cursor hidden (`CURSOR_SHOWING` off) | `visible:false` → overlay hidden (matches remote) |
| Cursor on secondary monitor | `visible:false` (never render clamped-edge coords) |
| Session locked / secure desktop | `attachToInputDesktop()` best-effort; failure → `visible:false`, viewer falls back to crosshair+dot |
| Shape capture failure | Keep last good shape; if never succeeded, crosshair+dot fallback forever; never crash the poll loop |
| Old agent (no cursor events) | `hasCursorData=false` → exactly today's behavior |
| Animated cursors (handle reuse) | 500 ms pixel re-hash → new `shapeId` |
| High-DPI | % conversion uses `GetSystemMetrics` = same space as input injection; shape scale uses frame dims (cosmetic delta only if DPI virtualization skews them) |
| Agent disconnect/reconnect | Reset shape cache; hide overlay; control already auto-disables |
| Letterboxing | Overlay reuses `getLetterbox()`; verify at window sizes producing bars on both axes |
| Rapid shape flapping (resize edges) | ~1 RTT shape delay only (position is instant); payloads ~4 KB |
