# Show agent version in the dashboard device list

## Findings (from exploration)

The `agentVersion` pipeline is **already complete end-to-end** — only the device-list UI is missing the display:

- Agent sends `agentVersion` at enroll (`agent/src/main/enrollment.ts:151`) and in the 30s `agent:status` heartbeat (`agent/src/main/connection.ts:307`)
- Server persists it (`server/src/db/models/Device.ts:29`, default `'0.0.0'`) via `agentHandler.ts:51-56`, and returns it in both `GET /api/devices` (`server/src/routes/devices.ts:34`) and `dash:devices-update` (`server/src/socket/dashboardHandler.ts:68`)
- `DeviceInfo.agentVersion: string` already exists (`shared/src/protocol.ts:37`); zustand store carries it
- `DeviceDetail.tsx:44` already shows it; **`Devices.tsx` does not render it** in either table or grid view

Separately, the agent's version string is **hardcoded in 4 places** and can drift:
`agent/package.json:3` (`0.2.0`), `agent/src/main/enrollment.ts:9` (`const AGENT_VERSION`), `agent/src/main/index.ts:13` (duplicate const), `agent/src/main/electron.ts:68,101` (literal `'0.2.0'` in GUI state payloads). `getAgentVersion()` (`enrollment.ts:177-179`) just returns the constant.

Scope confirmed with user: show version in **both** table and grid views, and **include** the version-source cleanup.

(`v` prefix here because the grid has no column label; reuses `.device-card-time` style, no CSS changes)

### 2. Agent — single version source read from `package.json`

**`agent/src/main/enrollment.ts`:**
- Delete `const AGENT_VERSION = '0.2.0';` (line 9)
- Add `fileURLToPath` to the `node:url` imports (pattern already used at `electron.ts:24`)
- Rewrite `getAgentVersion()` (lines 177–179) to lazily read + cache the version from `join(dirname(fileURLToPath(import.meta.url)), '../../package.json')` (via existing `readFileSync`, `JSON.parse`), falling back to `'0.0.0'` on any read/parse error
- Line 151: `agentVersion: AGENT_VERSION` → `agentVersion: getAgentVersion()`

**`agent/src/main/index.ts`:**
- Delete `const AGENT_VERSION = '0.2.0';` (line 13)
- Add `getAgentVersion` to the existing `./enrollment.js` import (lines 1–9)
- Banner (line 17): `v${AGENT_VERSION}` → `v${getAgentVersion()}`

**`agent/src/main/electron.ts`:**
- Replace both `agentVersion: '0.2.0'` literals (lines 68, 101) with `getAgentVersion()` (already imported at line 15)

**Path resolution verified** — `src/main/` and `dist/main/` are both exactly two levels below `agent/`, so `../../package.json` resolves to `agent/package.json` in every mode:
- dev CLI (`tsx src/main/index.ts`) ✓
- compiled (`tsc` → `dist/main/`, `electron .`) ✓
- packaged: `electron-builder.yml` `files:` includes `package.json` at asar root; Electron's asar fs patching makes the read work from `app.asar/dist/main` ✓

## Out of scope (known limitations, left as-is)

- `device:status-update` relay (`agentHandler.ts:58-64`) omits `agentVersion`, so a version change mid-session appears only on the next device-list fetch / page reload — fine for this ask
- Search filter (`Devices.tsx:115-121`) does not match version
- `AgentHandshake.agentVersion` (`protocol.ts:164`) is declared but never sent by the agent — unchanged
- Devices that never sent a heartbeat will show the DB default `'0.0.0'` — shown as-is (honest)
