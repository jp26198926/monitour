# Fix: koffi ERR_MODULE_NOT_FOUND in packaged agent

## Problem

Installing the compiled agent on a client machine fails with:
```
Error [ERR_MODULE_NOT_FOUND]: Cannot find module
'...\resources\app.asar\node_modules\koffi\src\koffi\index.js'
```

## Root Cause

`agent/electron-builder.yml` line 40 excludes koffi's `src/` directory from the packaged app:

```yaml
- "!**/node_modules/koffi/src/**"
```

But koffi's entry points **depend on `src/` at runtime**:

1. `koffi/index.js` → `export from "./src/koffi/index.js"` (the main ESM loader)
2. `koffi/index.cjs` → `require("./src/koffi/index.cjs")` (the main CJS loader)
3. `koffi/src/koffi/index.js` line 221 → `import { loadStatic } from "./src/static.js"`

The `src/` directory contains **both** JS runtime files (needed) and C++ build sources (not needed). The blanket exclusion removes the JS loaders too, making koffi completely unloadable in the packaged app. Verified: the built `app.asar` has **zero** entries under `koffi/src/`, while `koffi/index.js` and `koffi/index.cjs` (which reference it) are present.

This was introduced in the prior packaging overhaul plan (`1794553220450-swift-falcon.md`), which even documented the contingency: *"If koffi misbehaves, widen back."*

## Fix

**File:** `agent/electron-builder.yml` (one line change)

Remove line 40 (`"!**/node_modules/koffi/src/**"`) from the `files` exclusions. Keep the `!**/node_modules/koffi/doc/**` exclusion (pure documentation, safe to omit).

Before:
```yaml
  - "!**/node_modules/koffi/src/**"
  - "!**/node_modules/koffi/doc/**"
```

After:
```yaml
  - "!**/node_modules/koffi/doc/**"
```

**Why not narrow the exclusion** to only strip C++ files (`*.cc`, `*.hh`, `abi/`, etc.)? Because `src/koffi/src/` mixes JS runtime files (`static.js`, `static.cjs`, `trampolines.cjs`) with C++ sources in the same directory. Selective glob exclusions would be fragile and easy to break on a koffi version bump. Including the extra ~400 KB of C++ sources is negligible for an installer and guarantees correctness.

**What stays as-is:**
- `asarUnpack: "**/*.node"` — already unpacks `@koromix/koffi-win32-x64/win32_x64/koffi.node` correctly (verified in `app.asar.unpacked`)
- `asarUnpack: "**/node_modules/koffi/build/**"` — harmless no-op (koffi 3.x has no `build/` dir)
- `!**/node_modules/koffi/doc/**` — safe, purely docs

## Verification

1. `cd agent && npm run build && npm run dist` — rebuild the installer
2. Inspect the built asar: `npx asar list agent/dist/win-unpacked/resources/app.asar | grep "koffi/src"` — should now show `koffi/src/koffi/index.js`, `koffi/src/koffi/index.cjs`, `koffi/src/koffi/src/static.js`, etc.
3. Run `agent/dist/win-unpacked/Monitour Agent.exe` — should start without ERR_MODULE_NOT_FOUND
4. Confirm koffi FFI works: the agent should connect and remote desktop input/cursor capture should function (these use `koffi.load('user32')` etc.)
