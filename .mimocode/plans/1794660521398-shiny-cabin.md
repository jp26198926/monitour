# Plan: Agent uninstall also removes the service + Task Scheduler entries (+ config wipe)

## Problem

Uninstalling the agent (Windows → Settings/Apps → NSIS uninstaller) only removes app files. Left behind:

1. **`MonitourAgent`** Task Scheduler entry (the auto-start service) — at next boot it runs a now-deleted exe.
2. **`MonitourLockCapture`** Task Scheduler entry (lock-screen capture helper, created on demand at `connection.ts:255`) — `removeLockCaptureTask()` (`service.ts:373`) is exported but **never called**; nothing removes it, not even the in-app "Uninstall Service" button.
3. **Agent identity/config** — `~/.monitour-agent` and the `%ProgramData%\Monitour` bootstrap copy (user chose full wipe on uninstall).

There is zero NSIS customization today (no `*.nsh` anywhere) — the uninstaller is stock electron-builder. Linux/macOS have no uninstaller at all (AppImage/dmg are just files); service cleanup there stays the in-app Settings → Uninstall Service, which already removes the systemd unit / launchd plist.

## Design (verified against `app-builder-lib` 26.x NSIS templates on disk)

- electron-builder **auto-includes `build/installer.nsh`** (default resource name — `NsisTarget.js:709`), into a shared header used by **both** the uninstaller and installer compiles (`NsisTarget.js:393,400,463,408`) → the `customUnInstall` macro will fire in the generated uninstaller.
- `!macro customUnInstall` runs at the **start of the uninstall section, before file deletion** (`uninstaller.nsh:156-158`, before the `# delete the installed files` block) — the right spot to stop the SYSTEM task instance so the exe isn't locked during removal.
- **Critical guard:** the uninstall section also runs during *updates* — the installer invokes the old uninstaller with `--updated` (`installUtil.nsh:202-224`). The macro MUST be wrapped in `${ifNot} ${isUpdated}` or every auto-update would wipe the service and config.
- On real uninstall the uninstaller runs elevated (perMachine), so plain `schtasks /delete` of the SYSTEM-created tasks works without extra UAC. `un.checkAppRunning` (`un.onInit`) already closes/kills the user-session app before the section runs.

## Changes

### 1. NEW `agent/build/installer.nsh`

```nsh
; Custom NSIS macros — auto-included by electron-builder (buildResources: build).
!macro customUnInstall
  ; Runs before file removal. During upgrades the uninstall section also runs
  ; (installer invokes the old uninstaller with --updated) — keep the service,
  ; tasks and agent identity so the updated app keeps working.
  ${ifNot} ${isUpdated}
    ; Stop task instances first so the exe isn't locked during file removal.
    nsExec::ExecToLog 'schtasks /end /tn "MonitourAgent"'
    nsExec::ExecToLog 'schtasks /delete /tn "MonitourAgent" /f'
    nsExec::ExecToLog 'schtasks /end /tn "MonitourLockCapture"'
    nsExec::ExecToLog 'schtasks /delete /tn "MonitourLockCapture" /f'

    ; Wipe agent identity/config: current user's, the SYSTEM service instance's
    ; (schtasks /ru SYSTEM => os.homedir() = systemprofile), and the shared
    ; bootstrap copy. ReadEnvStr avoids hardcoding C:\ProgramData.
    RMDir /r "$PROFILE\.monitour-agent"
    RMDir /r "$WINDIR\System32\config\systemprofile\.monitour-agent"
    ReadEnvStr $R0 "ProgramData"
    RMDir /r "$R0\Monitour"
  ${endif}
!macroend
```

Notes: `nsExec` ships with NSIS (no console flash); failures are ignored since tasks/config may not exist. Fallback if `nsExec` were ever unavailable: `ExecWait 'cmd /c ...'`.

### 2. `agent/electron-builder.yml` — nsis section

Add `deleteAppDataOnUninstall: true` — real uninstall also removes Electron userData dirs; internally guarded against updates (`uninstaller.nsh:224`).

### 3. `agent/src/main/service.ts`

- `uninstallWindowsTask()` (line 208): one elevated batch that stops + deletes **both** `MonitourAgent` and `MonitourLockCapture`, tolerant of missing tasks (`>nul 2>&1` + `exit /b 0`) — `uninstallService()` already decides success from `getServiceStatus()` (lines 120-121), so masking exit codes is safe and avoids spurious "Failed to remove task" errors when a task isn't present:

```ts
runElevatedBatch([
  `schtasks /end /tn "${SERVICE_NAME}" >nul 2>&1`,
  `schtasks /delete /tn "${SERVICE_NAME}" /f >nul 2>&1`,
  `schtasks /end /tn "${LOCK_TASK_NAME}" >nul 2>&1`,
  `schtasks /delete /tn "${LOCK_TASK_NAME}" /f >nul 2>&1`,
  `exit /b 0`,
]);
```

- **Delete `removeLockCaptureTask()`** (lines 373-382) — exported but never called anywhere; superseded by the above.

No changes to server, dashboard, or shared.
