# Plan: Realtime remote control — eliminate typing/input latency

> Replaces the previous plan (LAN-IP connectivity fix — completed).

## Problem

Control delay is obvious when driving the remote computer — especially typing. Confirmed identical on localhost and the LAN IP, so it is **not** the transport: it is the input-injection and frame-echo path.

## Root cause (verified in code)

1. **nut-js inserts mandatory sleeps before every input call** — the dominant cause:
   - `node_modules/@nut-tree-fork/nut-js/dist/lib/keyboard.class.js:22-28` — `config = { autoDelayMs: 300 }` + native `setKeyboardDelay(300)` at construction; `sleep(autoDelayMs)` before `type` (:45, per char!), `pressKey` (:81), `releaseKey` (:105).
   - `mouse.class.js:18` — `autoDelayMs: 100`, slept before pressButton/releaseButton/scroll (:106-258). `setPosition` is not slept.
   - `agent/src/main/inputInjector.ts:227-248` chains up to 9 awaited nut calls per keydown (modifier press x4 + key + modifier release x4) → **≥600 ms of pure sleep per typed character**, up to ~2.7 s with modifiers, serialized in `drainQueue` (:26-42). Typing builds a backlog → growing lag.
2. **Modifier model is wrong and slow** (`inputInjector.ts:227-248`): every keydown re-presses then RELEASES modifiers after the key — breaks chords (Ctrl+C) and adds awaits. The dashboard already sends explicit keydown/keyup for modifiers themselves (`RemoteDesktop.tsx:365-383`).
3. **Input queue starvation** (`inputInjector.ts:29-34`): coalesced `pendingMouseMove` is drained BEFORE queued key/button events — clicks/keystrokes wait behind mouse motion.
4. **Frame decode path** (`RemoteDesktop.tsx:46-76` `pump`): per frame `URL.createObjectURL(new Blob(...))` → async `img.onload` JPEG decode → `drawImage` — objectURL churn + serialized decode adds ≥1 frame of visible delay (keystroke effects appear late).
5. **No frame until the next capture tick** after input (`screenCapture.ts:50-64` fixed interval, 33 ms granularity at 30 fps).
6. **Transport order**: default `['polling','websocket']` (polling handshake first). Prefer ws-first for latency.

## Changes (ordered by impact)

### 1. `agent/src/main/inputInjector.ts` — kill the nut-js delays (the big one)

**1a.** Module top — zero the JS sleeps and the native keyboard delay (`providerRegistry` is a typed public export of nut-js; `config` fields are public mutable — no casts needed):

```ts
import { mouse, keyboard, Button, Key, Point, providerRegistry } from '@nut-tree-fork/nut-js';

keyboard.config.autoDelayMs = 0;
mouse.config.autoDelayMs = 0;
if (providerRegistry.hasKeyboard()) providerRegistry.getKeyboard().setKeyboardDelay(0);
```

**1b.** `keydown`/`keyup` → pure press-on-down / release-on-up via existing `resolveKey` (:154-164). Delete all per-event modifier flag handling (chords then work because Ctrl is held from its own keydown to its own keyup). Keep `keyboard.type(event.key)` fallback for unmapped single chars (punctuation):

```ts
case 'keydown': {
  enqueue(async () => {
    const nutKey = resolveKey(event.code, event.key);
    if (nutKey !== null) await keyboard.pressKey(nutKey);
    else if (event.key.length === 1) await keyboard.type(event.key);
  });
  break;
}
case 'keyup': {
  enqueue(async () => {
    const nutKey = resolveKey(event.code, event.key);
    if (nutKey !== null) await keyboard.releaseKey(nutKey);
  });
  break;
}
```

**1c.** `drainQueue` priority — queued key/button events first, coalesced mousemove last:

```ts
for (;;) {
  let fn = inputQueue.shift();
  if (!fn) { fn = pendingMouseMove; pendingMouseMove = null; }
  if (!fn) break;
  try { await fn(); } catch (err) { console.error('Input injection error:', err); }
}
```

### 2. Input-triggered capture "nudge" (`agent/src/main/screenCapture.ts` + `connection.ts`)

- `screenCapture.ts`: hoist capture state to module scope so the interval and the nudge share the `busy` guard (interval stays a singleton per AGENTS.md; `captureFrame()` stays the independent entry):

```ts
let active: { options: CaptureOptions; onFrame: (f: ScreenFrame) => void; busy: boolean } | null = null;
let lastNudge = 0;

export function nudge(): void {
  if (!active || active.busy) return;
  const now = Date.now();
  if (now - lastNudge < 40) return;
  lastNudge = now;
  const { options, onFrame } = active;
  active.busy = true;
  captureFrame(options).then(onFrame)
    .catch((e) => console.error('Nudge capture error:', e))
    .finally(() => { if (active) active.busy = false; });
}
```

  In `startCapture` (:47-72): set `active = { options, onFrame, busy: false }`, use `active.busy` in the interval body, clear `active = null` in the stop function.

- `connection.ts:104-105` (`server:desktop-input` handler): after `handleInputEvent(input);` add `if (input.type !== 'mousemove') nudge();` — a frame is captured immediately after keystrokes/clicks so feedback doesn't wait for the next tick. Import `nudge` alongside `startCapture` (:8).

### 3. `dashboard/src/pages/RemoteDesktop.tsx` — fast decode path (`pump`, :46-76)

Replace Blob→objectURL→`img.onload` with `createImageBitmap` (keep `pendingFrameRef`/`decodingRef` latest-frame-wins and the 1/s `setRtc` untouched; remove now-unused `imgRef`/`objectUrlRef` and the hidden `<img>`):

```ts
const pump = useCallback(() => {
  if (decodingRef.current) return;
  const data = pendingFrameRef.current;
  if (!data) return;
  pendingFrameRef.current = null;
  decodingRef.current = true;
  const canvas = canvasRef.current, ctx = canvas?.getContext('2d');
  if (!canvas || !ctx) { decodingRef.current = false; return; }
  createImageBitmap(new Blob([data as BlobPart], { type: 'image/jpeg' })).then((bmp) => {
    if (canvas.width !== bmp.width || canvas.height !== bmp.height) {
      canvas.width = bmp.width; canvas.height = bmp.height;
    }
    ctx.drawImage(bmp, 0, 0);
    bmp.close();
  }).catch((e) => console.error('Frame decode error:', e))
    .finally(() => { decodingRef.current = false; pump(); });
}, []);
```

### 4. WebSocket-first transport (`RemoteDesktop.tsx:110`, `Devices.tsx:72`)

```ts
io('/dashboard', { auth: { token }, transports: ['websocket', 'polling'], tryAllTransports: true });
```

`tryAllTransports` is a typed EngineOption (`engine.io-client/socket.d.ts:92`; `ManagerOptions extends EngineOptions`) and makes the client fall back to polling when the ws upgrade is blocked (preserves the earlier LAN-IP fix).

## Risks / notes

- **autoDelay=0**: held keys now produce OS key-repeat (desired); very rapid synthetic clicks may register as double-clicks; a few apps debounce near-instant synthetic input (rare).
- **Chord semantics change**: modifiers stay held until their keyup (the fix). A lost keyup could leave a modifier stuck — acceptable; a release-all hook can be added later if observed.
- **Nudge**: one extra JPEG capture per discrete input burst (40 ms throttle, shares the busy flag).
- **ws-first**: proxies that block `Upgrade` fall back to polling automatically.
- Locked-screen path (`winInput.ts` koffi SendInput) is untouched — already zero-delay.
